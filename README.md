# FireDrop

**Быстрая передача файлов и целых папок по локальной Wi-Fi сети: с компьютера на
телефон, с телефона на компьютер и с телефона на телефон.**

FireDrop работает без интернета, облака, регистрации и аккаунтов. На компьютере
запускается портативный `FireDrop.exe`, который поднимает локальный сервер и показывает
QR-код с кодом доступа. Телефон отправляет файлы либо через страницу в браузере, либо
через приложение FireDrop для Android. Приложение также умеет принимать файлы, поэтому
два телефона могут передавать их напрямую друг другу.

Исходный код: https://github.com/ArhonTs/FireDrop — лицензия GNU GPL v3.

В версии **1.2.1** в настройках Windows появилась кнопка «Разрешить FireDrop в сети»:
если после обновления телефон перестал видеть компьютер — нажмите её и подтвердите
запрос Windows. Также добавлены страница «О приложении» в обоих приложениях и
ускоренное распознавание QR-кодов (с версии 1.2.0).

В **1.2.2** телефон предупреждает на экране «Принять», если на нём активен VPN или
адрес не из домашней подсети (например, `10.x.x.x` в гостевой Wi-Fi сети): так сразу
видно, почему компьютер не может к нему подключиться.

В **1.2.3** в списке адресов на ПК снова видны все варианты сетей, как в первой версии:
Wi-Fi первым, затем виртуальные адаптеры (VMware, Hyper-V, WSL, Docker) с пометкой
«(виртуальный)». Выбрать адрес можно кнопкой рядом с адресом внизу окна — QR-код и
ссылка сразу меняются.

## Что входит в выпуск

| Файл | Назначение |
| --- | --- |
| `FireDrop.exe` | Приложение для Windows 10/11 x64, ничего устанавливать не нужно |
| `FireDrop-1.2.3.apk` | Приложение для Android 8.0 и новее |
| `README.md` | Эта инструкция |
| `SHA256SUMS.txt` | Контрольные суммы файлов |

Windows-приложение и Android-приложение умеют и отправлять, и принимать: файлы идут
напрямую между устройствами без облака.

## Быстрый старт: телефон → компьютер

1. Запустите `FireDrop.exe` на компьютере.
2. Если Windows покажет запрос брандмауэра, разрешите доступ **для частных сетей**.
   Если момент упущен — не страшно: в настройках FireDrop есть кнопка
   «Разрешить FireDrop в сети» (см. раздел «Брандмауэр Windows»).
3. Подключите телефон к той же Wi-Fi сети, что и компьютер.
4. Отсканируйте QR-код с экрана компьютера камерой телефона — откроется страница
   FireDrop. Либо установите Android-приложение и нажмите в нём **«Отправить»**.
5. Выберите файлы (или папку, если браузер это поддерживает) и дождитесь окончания
   передачи.
6. Файлы появятся в папке, указанной в настройках. По умолчанию это
   `C:\Users\<имя>\Downloads\FireDrop`.

Если камера не открывает ссылку, введите адрес с экрана компьютера вручную
(например, `http://192.168.1.104:47820`) и шестизначный код доступа.

### Отправка из браузера

Страница FireDrop открывается по QR-коду или адресу. На ней можно выбрать отдельные
файлы, фото и видео, снять снимок камерой или выбрать **папку** — тогда на компьютере
сохранится вся структура вложенных папок.

Выбор папки поддерживается в настольных Chrome, Edge, Opera и других браузерах на
Chromium. На телефоне надёжнее приложение FireDrop: оно умеет выбирать папки на любой
поддерживаемой версии Android. В Safari на iPhone кнопки выбора папки нет — выбирайте
файлы по одному или используйте приложение.

### Отправка из Android-приложения

1. Установите APK (см. раздел «Установка на Android»).
2. Подключите телефон к той же Wi-Fi сети.
3. Откройте **«Отправить»**.
4. Нажмите **«Найти рядом»** и выберите компьютер в списке либо **«QR»** и отсканируйте
   QR-код с экрана компьютера.
5. Если адрес введён вручную, введите шестизначный код с экрана компьютера.
6. Нажмите **«Файлы»** или **«Папка»**, выберите содержимое и отправьте.

Сканирование QR-кода компьютера подставляет адрес и токен — код вводить не нужно.

## Передача телефон → телефон

Оба телефона должны быть подключены к одной Wi-Fi сети. На обоих должно быть
установлено приложение FireDrop.

1. На принимающем телефоне откройте **«Принять»** и нажмите **«Включить приём»**.
   Разрешите уведомления, если система спросит.
2. На экране появятся QR-код, шестизначный код и адрес вида `http://192.168.1.55:47820`.
   Приём продолжится, даже если свернуть приложение — в уведомлении будет кнопка
   «Остановить».
3. На отправляющем телефоне откройте **«Отправить»**, нажмите **«Найти рядом»** и
   выберите телефон в списке. Либо нажмите **«QR»** и отсканируйте QR-код с экрана
   принимающего телефона.
4. Введите шестизначный код (при сканировании QR он подставится сам).
5. Выберите файлы или папку и отправьте.

Принятые файлы сохраняются на телефоне в **Download/FireDrop**. Структура папок
сохраняется. На Android 10 и новее система не позволяет создавать пустые папки через
MediaStore, поэтому пустые каталоги пропускаются; файлы всегда создают свои папки.

Передача идёт напрямую между телефонами по Wi-Fi, без компьютера и без интернета.
Браузерная страница есть только на компьютере: для приёма на телефон нужно приложение
FireDrop на обоих устройствах.

## Отправка с компьютера на телефон

Компьютер отправляет файлы на телефон, где включён приём в приложении FireDrop.

1. На телефоне откройте **«Принять»** и нажмите **«Включить приём»**. На экране появятся
   QR-код и шестизначный код приёма.
2. На компьютере нажмите кнопку с самолётиком в строке заголовка окна — откроется панель
   **«Отправить на телефон»**.
3. Укажите получателя любым способом:
   - нажмите **«Найти рядом»** и выберите устройство из списка;
   - или отсканируйте QR-код с экрана телефона любым QR-считывателем и вставьте текст
     вида `firedrop://send?…` в поле адреса — адрес и код подставятся сами;
   - или введите вручную адрес вида `192.168.1.55:47820` и шестизначный код.
4. Нажмите **«Файлы…»** или **«Папка…»** и выберите содержимое. При отправке папки на
   телефоне сохранится вся структура вложенных каталогов.
5. Нажмите **«Отправить»** и дождитесь окончания.

Принятые файлы появятся на телефоне в `Download/FireDrop`. Передача идёт по Wi-Fi,
без интернета.

## Папки

- При отправке папки сохраняется её имя и все вложенные каталоги.
- Если на приёмнике уже есть файл с таким именем, он не перезаписывается: рядом
  появится `имя (1).ext`, `имя (2).ext` и т. д.
- Одноимённые папки объединяются, файлы внутри обрабатываются по правилу выше.
- Браузер не умеет выбирать пустые папки — это ограничение HTML. Пустые папки можно
  передать только из Android-приложения на компьютер.
- На Windows пустые папки создаются; на Android 10+ они пропускаются (см. выше).
- Слишком длинные и недопустимые имена очищаются, а вложенность ограничена разумными
  пределами, чтобы файлы не попали за пределы папки сохранения.

## Установка на Android

Требуется Android **8.0** (API 26) или новее. Приложение не использует Google Play
Services, AndroidX и лишние библиотеки, поэтому занимает около 300 КБ.

1. Скопируйте `FireDrop-1.2.3.apk` на телефон любым способом: кабелем, через файловый
   менеджер или скачайте файл в браузере телефона.
2. Откройте APK в файловом менеджере или в уведомлении о загрузке.
3. Если система попросит, разрешите установку из этого источника:
   **«Настройки» → «Установка неизвестных приложений»** → выберите файловый менеджер
   или браузер → **«Разрешить»**.
4. Нажмите **«Установить»**. Play Protect может предупредить, что приложение не из
   магазина: выберите **«Подробнее» → «Всё равно установить»**. APK подписан локальным
   ключом, поэтому такие предупреждения ожидаемы.
5. На Android 13 и новее разрешите уведомления — иначе не будет видно состояние приёма.
6. На Android 9 и ниже разрешите доступ к памяти, иначе принятые файлы не сохранятся
   в «Загрузки».

Обновления ставятся поверх старой версии. Для этого APK должен быть подписан тем же
ключом, что и предыдущий.

Приём на некоторых телефонах (Xiaomi, Redmi, Huawei, Honor, Samsung) может
останавливаться системой из-за экономии батареи. Разрешите приложению работу в фоне:
**«Настройки» → «Приложения» → FireDrop → «Батарея» → «Без ограничений»** (названия
пунктов зависят от прошивки).

## Требования

- Windows 10 (22H2) или Windows 11, 64-битная. .NET устанавливать не нужно:
  `FireDrop.exe` — самодостаточная сборка.
- Android 8.0 или новее для приложения.
- Телефон и компьютер (или два телефона) в одной локальной Wi-Fi сети.
- Современный браузер: Chrome, Edge, Firefox, Safari или Samsung Internet.
- На роутере должна быть отключена изоляция клиентов (AP/client isolation), а сеть —
  не гостевая.

## Возможности

- Передача файлов и папок с сохранением структуры каталогов.
- Прямая запись на диск без облака, base64 и multipart-обёрток.
- До шести параллельных потоков по 8 МБ: скорость ограничена в основном Wi-Fi.
- QR-код для мгновенного подключения и шестизначный PIN как резервный способ.
- Поиск устройств в локальной сети: компьютер и телефоны отвечают на UDP-запрос.
- Защита соединения случайным токеном в QR-ссылке и PIN-кодом с ограничением попыток.
- Сохранение без перезаписи: к повторяющимся именам добавляется `(1)`, `(2)` и т. д.
- Недописанные файлы лежат во временной папке и не засоряют папку загрузок.
- Windows: выбор сетевого адаптера, папки сохранения, порта, автозапуск, работа в трее.
- Android: выбор имени устройства, порта приёма, отправка и приём в одном приложении.
- Интерфейс и мобильная страница полностью на русском языке.

## Скорость

Чтобы получить максимальную скорость:

- выбирайте сеть **5 ГГц** или Wi-Fi 6/7, а не 2,4 ГГц;
- держите телефон рядом с роутером;
- отключите VPN на телефоне — он может направить трафик через интернет;
- не блокируйте экран отправляющего телефона: приложение само удерживает его включённым
  во время передачи;
- на принимающем телефоне приём идёт в foreground-сервисе с wake-lock, но экономия
  батареи может его ограничить — см. раздел про Android;
- убедитесь, что на роутере отключена изоляция клиентов;
- не используйте гостевую Wi-Fi сеть одновременно с основной.

Ориентир: в тестовой локальной сети передача шла со скоростью около **30 МБ/с**.
На гигабитном Wi-Fi 5/6 и хорошем сигнале скорость может быть выше. Реальная скорость
зависит от телефона, роутера, расстояния и помех.

При приёме на Android файл сначала записывается во временную папку, а затем
публикуется в MediaStore. Для очень больших файлов публикация может занять некоторое
время после окончания передачи — не закрывайте приложение, пока оно не покажет
«готово».

## Безопасность

- Сервер работает только в локальной сети и не обращается в интернет.
- Доступ открывается по ссылке с секретным токеном из QR-кода или по шестизначному
  PIN-коду. После нескольких неверных попыток вход временно блокируется.
- Соединение использует HTTP внутри вашей Wi-Fi сети. Не запускайте FireDrop в
  общедоступных сетях и не передавайте через него секретные документы в недоверенной
  сети.
- Ссылка и PIN-код дают доступ к приёму файлов. Не показывайте их посторонним.
- Приём на Android продолжается в фоне, пока включён сервис. Остановите его кнопкой
  в приложении или в уведомлении, если он больше не нужен.

## Настройки Windows

Откройте **«Настройки»** кнопкой с ползунками в правом верхнем углу.

- **Имя компьютера** — так устройство подписывается на странице телефона и в списке
  «Найти рядом».
- **Папка сохранения** — куда складывать принятые файлы.
- **Порт** — по умолчанию `47820`. Если порт занят, укажите свободный от `1024` до
  `65535`; сервер и QR-код обновятся автоматически.
- **Запускать при входе в Windows** — добавляет приложение в автозапуск.
- **Сворачивать в трей при закрытии** — окно скрывается, но приём файлов продолжается.
  Выход из приложения — через меню иконки FireDrop в системном трее.

Настройки сохраняются в `%APPDATA%\FireDrop\settings.json`.

## Настройки Android

На главном экране приложения:

- **Имя устройства** — отображается у отправителя в списке найденных устройств.
- **Порт приёма** — по умолчанию `47820`. Новый порт применяется после перезапуска
  приёма.
- **Папка приёма** — `Download/FireDrop`, изменить её нельзя.

Приём включается на экране **«Принять»**. Пока сервис работает, в шторке уведомлений
висит постоянное уведомление с кнопкой остановки.

## Брандмауэр Windows и поиск устройств

Для приёма файлов нужен входящий **TCP-порт 47820** (или тот, который вы указали в
настройках). Для поиска устройства кнопкой **«Найти рядом»** дополнительно нужен
входящий **UDP-порт 47822**.

Правила брандмауэра Windows привязаны к точному пути `FireDrop.exe`. После обновления
приложения в новой папке (например, из свежего архива) старых правил у нового файла
нет: телефон перестаёт видеть компьютер, а «Найти рядом» не находит ничего в обе
стороны.

Самый простой путь: откройте **Настройки** FireDrop, найдите блок **«Брандмауэр
Windows»** и нажмите **«Разрешить FireDrop в сети»**. Подтвердите запрос Windows о
правах администратора — приложение само создаст оба правила для текущего пути и
порта. В том же блоке видно, разрешено ли подключение сейчас.

Если предпочитаете сделать правила вручную, выполните в PowerShell от имени
администратора:

```powershell
New-NetFirewallRule -DisplayName "FireDrop TCP" -Direction Inbound -Protocol TCP `
  -LocalPort 47820 -Action Allow

New-NetFirewallRule -DisplayName "FireDrop UDP" -Direction Inbound -Protocol UDP `
  -LocalPort 47822 -Action Allow
```

Кнопка в настройках всегда пересоздаёт правила с актуальным портом и путём
программы; при смене порта достаточно нажать её снова.

Поиск устройств необязателен: адрес и код всегда можно ввести вручную. На компьютере
адрес показан в нижней части окна, на принимающем телефоне — на экране «Принять».

## Если что-то не работает

### Компьютер не открывается с телефона

1. Убедитесь, что телефон и компьютер подключены к **одной** Wi-Fi сети, а не к гостевой.
2. Проверьте в нижней части окна FireDrop, что выбран адрес из сети, **где находится
   телефон** — обычно это Wi-Fi. Кнопкой рядом с адресом открывается список всех
   адресов компьютера: сначала Wi-Fi и Ethernet, затем виртуальные адаптеры
   (VMware, Hyper-V, WSL, Docker) с пометкой «(виртуальный)». Телефоны из обычной
   сети до виртуальных адресов не дойдут — они нужны лишь для тестируемых машин в
   тех же виртуальных сетях.
3. Разрешите FireDrop в брандмауэре Windows для частной сети (см. раздел выше).
4. Сверьте подсети: адрес телефона на экране приёма должен быть из той же сети, что и
   у компьютера (оба вида `192.168.1.x`). Адрес вида `10.x` означает гостевую Wi-Fi
   сеть, мобильный интернет или VPN — телефон предупредит об этом жёлтой подсказкой
   на экране «Принять». Подключите телефон к той же Wi-Fi сети, где компьютер.
5. Отключите VPN на телефоне и компьютере.
6. Проверьте, что на роутере не включена изоляция клиентов.
7. Убедитесь, что порт не занят другой программой. Приложение покажет ошибку и
   предложит сменить порт в настройках.
8. Если страница открывается, но файлы не отправляются, попробуйте другой браузер
   и не блокируйте экран до завершения передачи.

### «Найти рядом» ничего не находит

1. Проверьте, что принимающее устройство действительно работает: на компьютере сервер
   запущен, на телефоне включён приём.
2. Разрешите UDP-порт `47822` в брандмауэре Windows.
3. Убедитесь, что устройства в одной подсети. Некоторые роутеры разделяют сети 2,4 и
   5 ГГц или включают изоляцию клиентов.
4. Отключите VPN. Виртуальные адаптеры иногда перехватывают широковещательные пакеты.
5. Введите адрес вручную: на компьютере он показан в окне, на телефоне — на экране
   «Принять».

### QR-код не сканируется

1. Держите телефон так, чтобы QR-код целиком попадал в рамку, а камера была в фокусе
   (10–30 см от экрана).
2. Увеличьте яркость экрана компьютера.
3. Приложение сканирует в реальном времени. Если камера недоступна, на экране появятся
   кнопки **«Снять кадр для распознавания»** и **«Включить камеру заново»**: можно
   сфотографировать QR-код системной камерой или перезапустить сканер.
4. Если ничего не помогло, введите адрес и код вручную: на компьютере они показаны
   в нижней части окна.

### Телефон не принимает файлы

1. Откройте приложение и убедитесь, что приём включён и в уведомлении виден статус.
2. Разрешите уведомления на Android 13+.
3. Отключите оптимизацию батареи для FireDrop.
4. Проверьте, что на телефоне достаточно свободного места.
5. На Android 9 и ниже разрешите доступ к памяти.
6. Перезапустите приём кнопкой «Остановить» → «Включить приём».

### Передача прерывается или идёт медленно

1. Подойдите ближе к роутеру, выберите 5 ГГц.
2. Отключите VPN и энергосбережение на обоих устройствах.
3. Не блокируйте экран отправляющего телефона.
4. Проверьте свободное место на приёмнике.
5. Для очень больших файлов дождитесь завершения публикации: приложение показывает
   отдельное состояние сохранения.

### Принятые файлы не видны

На компьютере файлы лежат в папке из настроек, по умолчанию
`C:\Users\<имя>\Downloads\FireDrop`. На Android — в `Download/FireDrop`; откройте
файловый менеджер и раздел «Загрузки». Галерея показывает только медиафайлы, документы
и архивы ищите в файловом менеджере.

## Журналы и временные файлы

- Журнал Windows: `%APPDATA%\FireDrop\logs\firedrop.log`.
- Незавершённые загрузки Windows: `%APPDATA%\FireDrop\partial` — очищаются автоматически.
- Временные файлы Android: внутренняя папка приложения, очищаются при следующем запуске
  приёма.
- Диагностика Android через ADB:

  ```powershell
  adb logcat -s FireDrop
  ```

## SmartScreen и Play Protect

`FireDrop.exe` не подписан цифровым сертификатом. При первом запуске SmartScreen может
показать предупреждение. Нажмите **«Подробнее» → «Выполнить в любом случае»**, если вы
скачали FireDrop из доверенного источника. Приложение не требует прав администратора.

Android-приложение подписано самодельным ключом и распространяется вне Google Play,
поэтому Play Protect может показать аналогичное предупреждение. Это нормально для
локальной сборки.

## Проверка контрольных сумм

В архиве есть `SHA256SUMS.txt`. Проверить файлы в PowerShell:

```powershell
Get-FileHash .\FireDrop.exe -Algorithm SHA256
Get-FileHash .\FireDrop-1.2.3.apk -Algorithm SHA256
```

Сравните значения с `SHA256SUMS.txt`.

## Сборка из исходников

### Windows

Требуется [.NET 10 SDK](https://dotnet.microsoft.com/download).

```powershell
dotnet build .\FireDrop\FireDrop.csproj
dotnet publish .\FireDrop\FireDrop.csproj -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true `
  -p:EnableCompressionInSingleFile=true -o .\dist
```

Готовый файл: `dist\FireDrop.exe`. Это самодостаточная сборка для Windows x64 —
.NET на компьютере пользователя не требуется.

### Android

Нужны JDK 17, Android SDK Platform 34 и Build-Tools 34.0.0. Gradle и Android Studio не
требуются: APK собирается напрямую через `aapt2`, `javac`, `d8`, `zipalign` и
`apksigner`.

```powershell
.\Android\build.ps1 -Sdk "C:\Android\sdk" -Jdk "C:\Program Files\Java\jdk-17"
```

Результат: `Android\build\FireDrop-1.2.3.apk`.

Скрипт при первом запуске создаёт ключ подписи `Android\keystore\firedrop.jks`.
Сохраните его: обновления должны быть подписаны тем же ключом, иначе Android не
установит APK поверх старой версии. Параметры подписи заданы в `Android\build.ps1`.

Библиотека сканирования QR (`com.google.zxing:core 3.5.3`, лицензия Apache-2.0)
не хранится в репозитории: при первой сборке jar скачивается с Maven Central и
проверяется по SHA-256 — так же поступает и build-сервер F-Droid.

На Linux (в том числе на построевенном сервере F-Droid) работает тот же конвейер;
готовый APK остаётся непозначенным, его подписывает сервер F-Droid:

```bash
bash Android/fdroid-build.sh
```

Результат: `Android/build/FireDrop-unsigned.apk`. Нужны `ANDROID_HOME` с
Build-Tools 34.0.0 и платформой android-34, JDK 17 и `python3`.

## Публикация в F-Droid

F-Droid собирает Android-приложение сам из открытого исходного кода и подписывает
своим ключом. Подготовка выполнена, исходники выложены:
`https://github.com/ArhonTs/FireDrop` (тег `v1.2.3`), метаданные уже указывают
на этот репозиторий. Что остаётся сделать:

1. Проверьте сборку локально (Linux, WSL, Docker или Vagrant):

   ```bash
   git clone https://gitlab.com/fdroid/fdroiddata
   cd fdroiddata
   git clone https://github.com/ArhonTs/FireDrop
   cp FireDrop/metadata/ru.firedrop.app.yml metadata/
   fdroid build --verbose ru.firedrop.app
   ```

2. Отправьте merge request в `fdroiddata` с файлом `metadata/ru.firedrop.app.yml`.
   Сборка без Gradle описана кастомной командой `build:`, зависимость берётся
   из Maven Central по контрольной сумме.
3. Следующие версии подхватятся автоматически: новые теги `v1.2.4` и т. д.
   Изменения пишите в `Android/fastlane/metadata/android/*/changelogs/<versionCode>.txt`.

Важно понимать: APK из каталога F-Droid подписан ключом F-Droid, а APK из
`dist\` — вашим ключом `firedrop.jks`. Android не установит их друг поверх друга —
при переходе сначала удалите приложение. Пользователям каталога F-Droid будет
достаточно обычных обновлений из него.

## Структура проекта

- `FireDrop/` — исходный код WPF-приложения, встроенный ASP.NET Core-сервер и мобильный
  веб-интерфейс.
- `FireDrop/Core/TransferServer.cs` — маршруты, авторизация, папки и передача данных.
- `FireDrop/Core/UploadManager.cs` — приём чанков, имена файлов и запись на диск.
- `FireDrop/Core/DiscoveryService.cs` — ответы на UDP-поиск устройств.
- `FireDrop/Web/` — страница телефона на русском языке.
- `Android/app/java/ru/firedrop/app/` — исходники Android-приложения.
- `Android/app/java/ru/firedrop/app/ReceiverServer.java` — встроенный приёмник для
  передачи телефон → телефон.
- `Android/app/java/ru/firedrop/app/UploadTask.java` — отправка файлов и папок.
- `Android/build.ps1` — сборка APK без Gradle (Windows).
- `Android/fdroid-build.sh` — тот же конвейер для Linux; используется F-Droid.
- `metadata/ru.firedrop.app.yml` — метаданные сборки для каталога F-Droid.
- `Android/fastlane/metadata/` — описания и changelog на русском и английском.
- `LICENSE` — текст лицензии GNU GPL v3.
- `dist/` — готовая release-сборка Windows.
- `Android/build/` — готовый APK.
